# MyAI · 个人 AI 知识库助手

把你自己的文档变成"能问的"：用大白话提问，它从你的文档里找答案，**并且告诉你答案出自哪一篇**。

**没有使用任何 AI 框架** —— 请求怎么发、上下文怎么管、检索怎么做、工具怎么调，每一层都是自己实现的，一共 7 个模块 2151 行 Python。

从命令行工具开始，最后收敛成一个网页界面，**并跑通了自己的手机在校园网下远程访问**。

---

## 能做什么

### 1. 知识库问答（RAG）

把文档放进 `docs/`（或私有的 `mydocs/`），建一次库，之后就能按"意思"检索并按文档回答，**而且会标出来源**：

```
$ python ask.py "我出差自己先垫的钱，什么时候能要回来？"

实际用的检索词（1 条）：
  · 出差费用报销时间

检索到 3 个相关片段：
  1. 相似度 0.516   公司规章制度.md
  2. 相似度 0.491   采购-供应商准入与评估.md

AI > 报销需在费用发生当月起的 60 天内提交，超期不予受理。[公司规章制度.md]
```

### 2. 一句话问多个问题，也能全答对

这是实测出来的一个真实问题：一次问三件事，只答对 1 个；实现了**查询分解**之后 **3/3**。（细节见下面「实测记录」）

```
$ python ask.py "进程和线程的区别是什么？死锁的四个必要条件是哪四个？页面置换算法有哪些？"

实际用的检索词（3 条）：
  · 进程 线程 区别   · 死锁 四个必要条件   · 页面置换算法

AI > - 进程与线程的区别：进程是资源分配的基本单位，线程是处理机调度的基本单位……
     - 死锁的四个必要条件：互斥条件、不剥夺条件、请求和保持条件、循环等待条件。
     - 页面置换算法有：最佳置换(OPT)、先进先出(FIFO，可能出现Belady异常)、
       最近最久未使用(LRU)、时钟置换(CLOCK)、改进型时钟置换。    [操作系统.txt]
```

### 3. 工具调用（Agent）

给模型 5 个工具（查时间、算数、读文件、写文件、查知识库），**它自己判断该用哪个**：

```
$ python agent.py "我们公司报销要在多少天内提交？"
第 1 轮  【模型决定：调用 search_knowledge_base】参数：{"query": "报销提交时限"}
第 2 轮  【模型决定：不再调用工具，直接回答】
        报销需在费用发生当月起的 60 天内提交，超期不再受理。

$ python agent.py "用一句话讲讲什么是流式输出"
第 1 轮  【模型决定：不再调用工具，直接回答】
        （闲聊类问题不查资料，直接回答）
```

### 4. 网页界面 + 手机远程访问

```cmd
streamlit run app.py
```

- **流式回答**、**标注来源**（可展开看依据了哪几段、相似度多少）
- **上传文档**：txt / md / pdf / docx / xlsx，保存后自动重建知识库
- **一键重建**、**可关掉"查资料"**（开关一拨，同一个问题对比一下就知道 RAG 有什么用）
- **访问密码**：对外开放前先上锁
- **手机远程访问**：用蒲公英组网（私有网络），手机在任何网络下都能打开自己的知识库

### 5. 多轮对话

```cmd
python chat.py --system "你是一个毒舌吐槽助手"
python chat.py --resume              ← 关掉程序再打开，接着上次聊
```

对话自动存进 `sessions/`，每聊完一轮存一次，强关也不丢。

## 快速开始

需要 Python 3.9+。

```cmd
git clone https://github.com/gaozhe114514/myai.git
cd myai

python -m venv .venv
.venv\Scripts\activate

pip install -r requirements.txt
copy .env.example .env
```

然后编辑 `.env`，填上你的接口地址和密钥：

```
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_API_KEY=sk-你的key
```

> **国内装依赖一定要加镜像**，不然会非常慢（实测差 160 倍）：
> `pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

跑起来：

```cmd
python chat.py "你好"                              ← 先试这一句
python ingest.py                                   ← 建知识库（第一次会下模型，约 95MB）
python ask.py "报销要在多少天内提交？"
python agent.py "现在几点？"

streamlit run app.py                               ← 网页界面
```

## 它是怎么工作的

### 上下文：模型本身没有记忆

模型每次都是"失忆"的。所谓"它记得上一句"，其实是程序把**整段对话历史每一轮都重新发一遍**。记忆在程序里，不在模型里。这也是"聊得越久越贵"的原因。

### RAG：不是让模型读更多，是别让它读那么多

```
文档 → 切块 → 每块算一个向量（512 维）→ 存进向量库
                                          ↓
提问 → 拆问题 → 逐条改写 → 逐条检索 → 合并去重 → 只把这几块发给模型
```

**检索这一层做了三次加工**，每一步都是实测有效才加的：

| 步骤 | 解决什么 | 实测效果 |
|---|---|---|
| **切块 + 重叠** | 关键句被切点在中间切断了 | — |
| **查询改写** | 口语问题 vs 文档用语对不上 | 正确答案从**第 6 名**升到**第 1 名** |
| **查询分解** | 一句话问多件事，检索被稀释 | **答对率 1/3 → 3/3** |

### Agent：一个循环

```
把问题 + "你有哪些工具"发给模型
  ↓
模型说："我要调用 search_knowledge_base，参数是 xxx"
  ↓
我的程序去执行那个函数，把结果作为一条 tool 消息发回去
  ↓
带着新信息再问一次 → 回到第一步
  ↓
直到模型不再要求调工具，给出最终回答
```

**模型自己执行不了任何东西。** 它只能"请求"，真正动手的是 Python 代码 —— 所以所有的安全措施都在程序这一层。

## 实测记录

这个项目里所有的设计选择，都尽量用数字说话，而不是"我觉得这样更好"。

**① 查询改写：正确答案从第 6 名升到第 1 名**

问`"我出差自己先垫的钱，什么时候能要回来？"`，正确文档在 27 个块里排第 6 名（相似度 0.411），检索不到。
先让模型改写成"出差费用报销时间"再检索 → 排**第 1 名**（0.516）。

**② 查询分解：答对率 1/3 → 3/3**

一次问三个问题（进程线程、死锁、页面置换），只答对 1 个。
逐个排查确认：文档里三个主题都有，单独问也全都能检索到 —— 问题是**三个问题被合成了一条检索词**，被其中出现频率最高的那个主题占满了。
拆开分别检索后：

```
关掉分解：1 条检索词 → 3 块  → 答对 1/3
打开分解：3 条检索词 → 9 块  → 答对 3/3     （发出内容 1495 字 → 4081 字）
```

> 有个反直觉的细节：**合并后的相似度反而更高**（0.661 > 0.610），但结果更差。这印证了下面第 ④ 条。

**③ 上下文窗口的真实大小**

用一个必定超限的文件去撞，让服务端自己报出上限：

```
maximum context length is 1048576 tokens
you requested 2800087 tokens
```

换算下来：**1 个中文字 ≈ 0.54 token**，上限约 **195 万字**。

那把 50 个文件（4.7 万字）直接塞进 prompt 呢？只占窗口的 **2.4%** —— 所以"50 个文件塞不下"这个担心是错的，**瓶颈是字数不是文件个数**。真正的问题是：每轮都要全额重发那 4.7 万字，又贵又稀释注意力。这就是 RAG 存在的理由。

**④ 怎么判断检索是好是坏**

看相似度分数**有没有拉开差距**，而不是看绝对值。

- `0.652 / 0.607 / 0.523` → 头名明显领先，找对了
- `0.484 / 0.445 / 0.430 / 0.429 / 0.418 / 0.411` → 全都挤在 0.4 出头，谁也没领先 → **根本没找着**

**⑤ 首屏体积：为什么"我自己秒开，别人打不开"**

Streamlit 是个 JS 单页应用，HTML 只有 1.5KB，真正的界面全在一个 **6.83 MB 的 JS 文件**里。
而免费版的组网工具是 2Mbps 中转（约 250 KB/s）→ 手机要下载 30 秒以上。

> 这就是"本地秒开、别人打不开"的经典原因：**你走 localhost 根本不用下载，别人要走网络下载。**

**⑥ 内存占用**

加载 embedding 模型后实测 **359 MB**（Streamlit 本身只有 67 MB）。所以部署至少需要 1核2G。

## 设计取舍与已知限制

**工具的安全边界**

`agent.py` 里的文件操作被限制在**当前工作目录**内，写文件前需要人工确认。

模型只能"请求"调用工具，真正执行的是我的代码 —— 所以这里是我唯一能拦住它的地方。实测越界路径（`../../Windows/win.ini`、`C:/Windows/win.ini`）和越界写入（`../hack.txt`）都会被拒绝，并把拒绝原因作为工具结果返回给模型（模型会据此换个做法，而不是卡死）。

数学计算用 `ast` 解析语法树，而不是 `eval()` —— `eval()` 会把字符串当**代码**执行。实测 `__import__('os').system(...)` 这类表达式会被直接拒绝。

**为什么不暴露到公网**

远程访问用的是**组网工具（蒲公英）**，不是内网穿透。区别在于：组网是把设备连成一个**私有网络**，只有自己的设备能进；内网穿透是把服务暴露到**公网**，谁拿到网址谁能进。前者安全得多，代价是每台设备都要装客户端。

即便这样也加了**访问密码** —— 因为网络里还会加设备，密码是最后一道闸。

**为什么不直接上向量数据库**

现在用的是 `rag_index.json` + 遍历比较。27～107 个块，快到看不见；**上 Milvus / FAISS 属于用大炮打蚊子**。

规模上来（几十万块、多用户并发、需要按元数据过滤）就该换，这个判断我清楚 —— 但不是现在。

**已知限制**

- **电脑必须开着** —— 网页跑在本机，关机就访问不了。想 7×24 就得租服务器
- **没有多轮记忆** —— `ask.py` 每次提问都是独立的
- **没有对话压缩** —— `chat.py` 的历史会一直增长，聊太久会超出上下文窗口
- **检索质量受限于 embedding 模型** —— 用的是 `bge-small-zh-v1.5`（95MB）。换成 `bge-m3` 能拿到稀疏检索那一路（关键词匹配），对"换个说法就找不到"的问题有帮助
- **没有评估集** —— 目前靠人工看相似度分数判断检索质量，没有自动化的评测
- **免费版组网限速 2Mbps** —— 查文字够用，第一次打开要等

**踩过的坑（有记录的）**

| 坑 | 原因 | 解法 |
|---|---|---|
| `pip install` 报 GBK 解码错误 | 中文 Windows 上 pip 用 GBK 读 UTF-8 的 requirements.txt | 给文件加 UTF-8 BOM |
| 装依赖慢到崩 | 官方 PyPI 只有 115 kB/s，下到一半断，哈希对不上 | 换国内镜像，快 160 倍 |
| 加载模型卡死 5 分钟 | `SentenceTransformer` 每次启动都要联网检查更新，网不通就一直重试 | `HF_HUB_OFFLINE=1`（已做成自动判断） |
| 手机打不开网页 | 不是网络，是 6.83MB 的前端包走 2Mbps 中转 | 耐心等，浏览器会缓存 |

## 技术栈

- **Python 3.9**，无 AI 框架
- **requests** — HTTP 请求
- **python-dotenv** — 读取 `.env` 配置
- **sentence-transformers** — 本地运行 embedding 模型（`BAAI/bge-small-zh-v1.5`，不用 API、不花钱）
- **pypdf / python-docx / openpyxl** — 解析 PDF、Word、Excel
- **Streamlit** — 网页界面
- **蒲公英** — 异地组网（手机远程访问）
- **模型** — DeepSeek `deepseek-flash`（OpenAI 兼容接口）
