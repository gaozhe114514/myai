# MyAI · 命令行 AI 助理

一个从零手写的命令行 AI 助手。能多轮对话，能读你给它的文档，能在文档库里检索，还能自己调用工具干活。

**没有使用任何 AI 框架** —— 请求怎么发、上下文怎么管、检索怎么做、工具怎么调，每一层都是自己实现的，一共 7 个模块 2151 行 Python。

---

## 能做什么

### 1. 多轮对话，并支持换人设、换模型、恢复历史

```cmd
python chat.py --system "你是一个毒舌吐槽助手"
python chat.py --resume              ← 关掉程序再打开，接着上次聊
python chat.py --model deepseek-chat
```

对话自动存进 `sessions/`，每聊完一轮存一次，强关也不丢。

### 2. 知识库问答（RAG）

把文档放进 `docs/`，建一次库，之后就能按"意思"检索并按文档回答，**而且会标出来源**：

```
$ python ask.py "我出差自己先垫的钱，什么时候能要回来？"

改写后的检索词：出差费用报销时间

检索到 3 个相关片段：
  1. 相似度 0.516   公司规章制度.md
  2. 相似度 0.491   采购-供应商准入与评估.md
  3. 相似度 0.465   人事-新员工入职指引.md

AI > 报销需在费用发生当月起的 60 天内提交，超期不予受理。[公司规章制度.md]
```

### 3. 工具调用（Agent）

给模型 5 个工具（查时间、算数、读文件、写文件、查知识库），**它自己判断该用哪个**：

```
$ python agent.py "现在几点？"
第 1 轮  【模型决定：调用 get_current_time】参数：{}
第 2 轮  【模型决定：不再调用工具，直接回答】
        现在是 2026 年 10 月 11 日 19:38:45。

$ python agent.py "我们公司报销要在多少天内提交？"
第 1 轮  【模型决定：调用 search_knowledge_base】参数：{"query": "报销提交时限"}
第 2 轮  【模型决定：不再调用工具，直接回答】
        报销需在费用发生当月起的 60 天内提交，超期不再受理。
```

同一个入口，模型自己分派 —— 涉及公司制度的问题去查文档，闲聊的问题直接回答。

### 4. 网页界面

```cmd
streamlit run app.py
```

浏览器会自动打开。左边是设置（模型、人设、知识库管理），右边是聊天窗口。

界面上的东西：

- **流式回答** —— 一个字一个字往外蹦，不是卡住然后整段出现
- **标注来源** —— 每段回答下面可以展开看"依据了哪几段资料、相似度多少"
- **一键重建知识库** —— 上传文档后点一下就行，不用敲命令
- **可以关掉"查资料"** —— 同一个问题，开/关对比一下，就知道 RAG 到底有什么用

支持上传 **txt / md / pdf / docx**。

## 快速开始

需要 Python 3.9+。

```cmd
git clone <这个仓库的地址>
cd ClaudecodeDemo1

python -m venv .venv
.venv\Scripts\activate

pip install -r requirements.txt
copy .env.example .env
```

然后编辑 `.env`，填上你的接口地址和密钥：

```
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_API_KEY=sk-你的key
```

> **国内装依赖建议加镜像**，不然会非常慢：
> `pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`

跑起来：

```cmd
python chat.py "你好"                              ← 先试这一句
python ingest.py                                   ← 建知识库（第一次会下模型，约 95MB）
python ask.py "报销要在多少天内提交？"
python agent.py "现在几点？"

streamlit run app.py                               ← 网页界面
```

## 项目结构

```
chat.py         基础对话：多轮上下文、会话存档、/file 加载本地文件
rag_common.py   RAG 的共用工具：切块、向量化、检索、查询改写
ingest.py       建库：读 docs/ → 切块 → 算向量 → 存成 rag_index.json
ask.py          知识库问答：检索 → 拼 prompt → 回答并标出处
agent.py        工具调用：定义工具、执行工具、Agent 循环
docreader.py    从 txt / md / pdf / docx 里把纯文本抠出来
app.py          网页界面（Streamlit）
config.json     默认配置（模型、人设、超时）
docs/           你的文档放这里
examples/       agent 演示用的测试文件
```

## 它是怎么工作的

### 上下文：模型本身没有记忆

模型每次都是"失忆"的。所谓"它记得上一句"，其实是 `chat.py` 把**整段对话历史每一轮都重新发一遍**。记忆在程序里，不在模型里。

这也是"聊得越久越贵"的原因 —— 历史每轮都要重发，越来越长。

### RAG：不是让模型读更多，是别让它读那么多

```
文档 → 切块 → 每个块算一个向量（512 维）→ 存进向量库
                                                ↓
提问 → 把问题也算成向量 → 找最像的 3 块 → 只把这 3 块发给模型
```

关键在于**只发检索出来的那几块**，而不是整个文档库。

实测对比：把 50 个文件（4.7 万字）直接塞进 prompt，会发出 47,170 字；而 RAG 只发出约 950 字 —— **省了 98%**，而且因为噪声少了，回答还更准。

### Agent：一个循环

```
把问题 + "你有哪些工具"发给模型
  ↓
模型说："我要调用 search_knowledge_base，参数是 xxx"
  ↓
我的程序去执行那个函数，把结果作为一条 tool 消息发回去
  ↓
带着新信息再问一次 → 回到第一步
  ↓
直到模型不再要求调工具，给出最终回答
```

**模型自己执行不了任何东西。** 它只能"请求"，真正动手的是 Python 代码 —— 所以所有的安全措施都在程序这一层。

## 设计取舍与已知限制

这个项目在几个地方做了刻意的简化，以及一些实测发现：

**1. 工具的安全边界**

`agent.py` 里的文件操作被限制在**当前工作目录**内，写文件前需要人工确认。

这不是多此一举。模型只能"请求"调用工具，真正执行的是我的代码 —— 所以这里是我唯一能拦住它的地方。实测越界路径（`../../Windows/win.ini`、`C:/Windows/win.ini`）和越界写入（`../hack.txt`）都会被拒绝，并把拒绝原因作为工具结果返回给模型（模型会据此换个做法，而不是卡死）。

数学计算用 `ast` 解析语法树，而不是 `eval()` —— `eval()` 会把字符串当**代码**执行，如果表达式里出现 `__import__('os').system(...)`，那就是任意代码执行。实测这类表达式会被直接拒绝。

**2. 查询改写大幅提升了检索命中率**

embedding 模型对"换个说法"很敏感。实测：问"我出差自己先垫的钱什么时候能要回来"，正确文档在 27 个块里排**第 6 名**（相似度 0.411），检索不到；先让模型改写成"出差费用报销时间"再去检索，就排**第 1 名**（0.516）。所以 `ask.py` 和 `agent.py` 里都加了改写这一步。

**3. 怎么判断检索是好是坏**

看相似度分数**有没有拉开差距**，而不是看绝对值。第一名 0.65、第二名 0.60 → 找对了；全都挤在 0.4 出头 → 根本没找着，这时候模型答"资料里没有"是正确的，不是它笨。

**4. 已知限制**

- **没有多轮记忆**：`ask.py` 每次提问都是独立的，没有对话上下文
- **没有对话压缩**：`chat.py` 的历史会一直增长，聊太久会超出上下文窗口
- **检索质量受限于 embedding 模型**：用的是 `bge-small-zh-v1.5`（95MB），换成更大的模型效果会更好，但速度会慢
- **没有评估集**：目前靠人工看相似度分数判断检索质量，没有自动化的评测

## 技术栈

- **Python 3.9**，无 AI 框架
- **requests** — HTTP 请求
- **python-dotenv** — 读取 `.env` 配置
- **sentence-transformers** — 本地运行 embedding 模型（`BAAI/bge-small-zh-v1.5`）
- **pypdf / python-docx** — 解析 PDF 和 Word
- **Streamlit** — 网页界面
- **模型** — DeepSeek `deepseek-flash`（OpenAI 兼容接口）
